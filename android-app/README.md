# 鲸鲸约跑

> **作者：WilliTourt的蓝色大肥鱼 🐟** · v1.11.0

替你跑完这两公里 · 你只管去刷脸。

**不申请定位权限，不连服务器，不需要登录。**

适用于 HarmonyOS 4.0（Android 12 基底）及所有 Android 7.0+ 设备。

---

## 界面结构

**一个 Activity + 四个 panel**，底部一条悬浮切换栏。切页只改 `visibility`，
不重建 Activity，也不引 Fragment / 导航库（守住「零第三方依赖」）。

```
主页                        统计
├── 跑步区域                └── 成绩汇总 / 分场地 / 最近记录
├── 配速 / 距离
├── 配速抖动
├── 轨迹毛刺开关（默认关）    上手
├── 电池白名单提示           ├── 使用教程
├── 开始 / 结束打卡          ├── openid 输入 + 连接并拉取场地
└── 实时仪表盘              └── 取码（openid 说明 + 提取脚本）
（顶栏右上角小图标进【日志】页）

                            设置
                            ├── 主题（跟随系统 / 深色 / 浅色）
                            ├── 说明信息
                            ├── 开源仓库
                            └── 署名
```

对应布局：`activity_main.xml`（顶栏 + 4 个 `<include>` + 悬浮栏）
与 `panel_run / panel_stats / panel_start / panel_settings.xml`。
四个 panel 的 `id` 全局唯一，`MainActivity.showTab()` 切可见性。

> openid 填在【上手】页。填完切回主页时会**自动刷新场地列表**（`AreaStore` +
> `onResume` 里的 `syncAreas()`），不需要先点一次【开始打卡】。

主题切换在【设置】页，是「跟随系统 / 深色 / 浅色」三段式，不是一个循环按钮。

### 连不上服务器时

点【连接并拉取场地】如果拉不到数据，会弹一个明确的对话框（而不是默默留一个空列表）：

```
无法连接到服务器

连不上 sport.cqupt.edu.cn，场地列表没拉下来。

请检查：
· 手机是否连着网（校园网可能需要先登录）
· 能否正常打开微信小程序「重邮智慧体育」
· 稍等片刻再点一次「连接并拉取场地」
```

实现上把「网络层失败」和「业务层失败」分开了：`Api` 返回 `null` 是前者
（弹上面这个框），返回了 JSON 但 `code != 10200` 是后者（提示 openid 未绑定之类）。
原来的实现把两者都塞进一个 `lastError` 字符串，界面上根本分不出来。

## 配速起伏与容差（v1.9.0 新增）

主页不再让你选配速形态 —— 轨迹固定使用**温和起伏**：

- 起步慢 → 中途数段快慢 → 越跑越累 → 尾声略冲
- 叠入约 7% 时长的短暂停顿（「系鞋带 / 等让路」式，2 公里约 2~3 次）

这是三层时间尺度叠加的结果：疲劳（整场）+ 地形（分钟级）+ 步频（十几秒级），
权重归一化到均值 1。

### 关键：起伏不参与达标判定

**总时长和总里程与匀速完全一致**，因为：

- 采样点数由 `配速 × 距离` 唯一确定（这点没变）
- 起伏只决定这些秒里的速度**怎么分配**，权重数组归一化到均值 = 1
- 距离标定的二分只负责把实测距离校准到目标值，与起伏互不干扰

实测（风华运动场，2000m，15 秒滚动窗口）：加入野点后窗口会明显变宽，
最快可到 **3'30" 左右**、最慢段受停顿影响可以很慢。
（滚动窗口才对应「跑者感受到的配速」—— 逐秒的瞬时配速在停顿处趋于无穷，取极值没意义。）

### 配速抖动（容差）

> 界面上叫「配速抖动」，代码里仍是 etTol / paceTol / paceToleranceSec ——
> 换的只是用户可见文案，机制没动。

主页多了一个「平均配速容差」输入，默认 **20 秒/公里**：

```
目标 5'45" + 容差 20s  →  平均配速被夹在 5'25" ~ 6'05"
```

生成后会校验实测平均配速是否落在窗口内，越界就按比例微调采样点数重算（最多 4 次），
保证不会因为 GPS 噪声下限或起伏形态而飘出 `minPace`/`maxPace` 达标区间。
窗口会在输入框下方实时显示。

单元测试 `配速窗口计算正确` 钉住窗口算法；`各种配速与种子下都不能越界`
在多个 seed / 配速下同时检查围栏与禁跑区。

### 汇报字段改成反推

`speed` / `bearing` 现在是从**最终坐标**反推的，不再独立生成。
这样上报的字段和轨迹严格自洽，不会出现「速度写着 3.0 m/s 但两点间距只有 1.2 米」。
单元测试 `轨迹形态要像人跑的，不是机器画的` 同时检查字段范围和逐点间距抖动。

## 轨迹毛刺与多尺度噪声（v1.11.0 新增）

原来的轨迹每个点只在 ±1~2m 内抖，4 圈几乎叠成同一条线，地图上是一条干净得可疑的
椭圆。v1.11.0 把「真人跑出来的 GPS 轨迹」拆成两层来做（由主页的开关控制）：

### 0. 「轨迹毛刺」开关（默认关闭）

主页在「配速抖动」下面新增一行开关，**默认关闭**，状态存在 SharedPreferences
（`burrs`）。开始打卡后开关会随其它跑步参数一起禁用，不能在跑的过程中切换。

- **关闭**：走 v1.10.1 的 `generateSmooth()` —— 两条低频正弦 + 单层 AR(1)，
  一条干净的光滑轨迹；
- **打开**：走下面的多尺度噪声 + 野点，地图上才会出现多圈错位和毛刺 / 突起。

参数链路：`MainActivity` → `RunController.start(burrs)` →
`RunEngine.runAll(burrs)` → `TrackGen.generate(burrs)`。`TrackGenTest` 用同一个
seed 对比两种模式：关闭时 5m+ 跳点必须为 0，打开后至少 8 个。

### 1. 路线本身更不规则

- 六条**整数圈**正弦（k = 2/3/5/7/11/17）叠加。整数圈保证绕一圈自动闭合，
  高频项负责把长直边揉出小波浪；
- 3~5 处局部鼓包（宽度 10~38m、幅度 ±2~6m），位置和符号都随机 —— 对应贴内道、
  绕人、抄近道留下的不对称；
- 只做一轮窗口为 2 的滑动平均，把最尖的折角磨掉，但不再磨平细节。

### 2. GPS 噪声分四层 + 稀疏野点

| 成分 | 量级 | 作用 |
|---|---|---|
| AR(1) ρ=0.997 | 分钟级 | 整圈贴着线内外漂，让 4 圈错开几米 |
| AR(1) ρ=0.97 | 十几秒 | 一段贴边、一段居中 |
| AR(1) ρ=0.85 | 几秒 | 摆臂 / 绕人的小摆动 |
| AR(1) ρ=0.55 | 一秒级 | 线边那圈碎锯齿 |
| 稀疏野点 | 0.8~16m | 1 秒尖刺 / 2 秒锯齿 / 4~9 秒三角绕行 / 偶尔大跳 |

野点密度按**总时长**换算（2km 和 5km 的每公里密度一致），全部只依赖下标和 seed，
和二分标定用的步长无关，所以配速标定不会被野点位置带偏。

### 3. 越界不再硬拽

旧版把越界点沿「点 → 质心」拉回边界，毛刺会被压成贴着围栏的直线。现在：

1. 先检查**未加噪声**的基准环是否合法，不合法就换下一档内缩；
2. 采样时越界，沿「基准点 → 噪声点」二分收短 —— 只削掉越界的那一截，
   毛刺的方向和形状都还在；
3. `clampToFence()` 只作为基准点本身非法的兜底。

[`refs/verify_pace_profile.py`](../refs/verify_pace_profile.py) 用 36 个组合
（3 场地 × 4 配速 × 3 seed + 起伏/容差检查）压过一遍：出界 0、禁跑区 0、
平均配速全部落在窗口内。新增的单元测试
`路线要有毛刺和突起，不能是光滑椭圆` 用跳点数量 / 最大跳距 / 每秒转向角
把这条行为钉住。

## 主题

设置页里三选一：**跟随系统 / 深色 / 浅色**。选择会记住。

实现方式是 AppCompat 的 `DayNight`：

| 资源 | 浅色 | 深色 |
|---|---|---|
| `values/colors.xml` | `#F2F5FA` 底 / `#16202F` 字 | — |
| `values-night/colors.xml` | — | `#0B1220` 底 / `#E8EEF7` 字 |

所有颜色（背景、卡片、描边、强调色、成功/危险色，连按钮上的文字色）都走资源引用，
没有一处写死。切主题时 `AppCompatDelegate` 会重建界面 —— 而跑步线程归单例所有，
所以**切主题不会影响正在进行的打卡**。

### 主题为什么要放在 Application

`AppCompatDelegate.setDefaultNightMode()` 写在 `Activity.onCreate()` 里会**先白闪一下**：

```
Activity.onCreate()
  ├─ super.onCreate()          ← 此时按「跟随系统」解析主题
  │                              系统是浅色就用浅色，窗口已经画出来了
  ├─ setDefaultNightMode(深色)  ← 才发现该用深色 → 触发 Activity 重建
  └─ setContentView()           ← 重建之后才是深色
```

这也解释了为什么**设成浅色就没这个问题** —— 浅色 + 系统浅色不需要改，不触发重建。

放到 `App.onCreate()` 里就没事了：Application 比任何 Activity 都早，
主题在 Activity 创建之前就定好，一次到位，不重建。

（`App` 类已注册在 manifest 的 `<application android:name=".App">`。）

## 后台保活（v1.6 重点）

**症状**：息屏 / 退出 App 几分钟后，进度条几乎不动，只有「用时」在涨。

**根因**——节拍循环是按"睡了几次"算时间的：

```kotlin
var slept = 0L
while (slept < 8000) {
    Thread.sleep(250)
    slept += 250      // ← 假设每次都正好睡 250ms
}
```

息屏后 CPU 被挂起，`Thread.sleep(250)` 实际可能睡 2 秒，但代码还傻乎乎地
`slept += 250`。所以"8 秒"的一批实际拖了 12 秒以上，**整轮被拖长一倍多**。

**三处修复**：

| 修复 | 做法 |
|---|---|
| 1. 按真实时间计节拍 | 改用 `SystemClock.elapsedRealtime()` 定目标时刻，睡过头就立刻跳过剩余等待 |
| 2. CPU 唤醒锁 | `RunService` 里持一把 `PARTIAL_WAKE_LOCK`，息屏后 CPU 不睡 |
| 3. 电池优化白名单 | 界面里有状态条，未加入时会引导跳系统设置。**深度 Doze 会连唤醒锁一起忽略，只有进白名单才彻底** |

第 3 点是关键：Android 的 Doze 模式下，系统会**忽略 wake lock、挂起网络**，
前台服务只能保证进程不被回收，保不住 CPU。所以第一次用的时候，
点一下那条黄色的提示，把 App 加进白名单（只需设置一次）。

另外日志现在每 10 批打一行，能看出它确实在动：

```
批次 10/99　已跑 0.20/2.00 km　用时 01:20
批次 20/99　已跑 0.40/2.00 km　用时 02:41
```

## 它做什么

```
你填一次 openid
      ↓
点【连接】→ 拉取跑步区域（服务器上的多边形）和配速规则
      ↓
```

**全程不碰 GPS。** 所以：

- 不需要开定位
- 不需要 root
- 不需要装 Xposed / VirtualXposed
- 不需要虚拟机、不需要改机

## 人脸打卡

**这部分我帮不了你，得你本人去。**

小程序里根本不调相机。它在 `jpq` 类型的区域里只做一件事：`wx.vibrateShort` 连震十下，
提醒你"该去扫脸了"。真正的人脸比对在操场上的物理摄像头里。

这一点在客户端的代码里能直接验证：小程序内只有 `wx.previewImage` 预览人脸图，没有调用相机做人脸比对。

所以配合方式是：**App 在后台（其实是前台）跑轨迹，你人在操场上走，挨个摄像头刷。**

## 常见问题

**Q：为什么不需要定位权限？**
A：因为根本不读 GPS。轨迹是本地算出来的，直接 POST 出去。

**Q：会被检测到是在伪造吗？**
A：服务端能看到的只有你 POST 的点。App 做了三件事让它看起来正常：
配速精确匹配（不是恒定值）、航向连续变化（不是几个固定方向）、
GPS 噪声符合真实手机的特征（AR(1) 相关噪声）。

**Q：日志里 `isBind=false` 怎么办？**
A：openid 不对。重新抓一次，注意别把 `openid=` 后面的 `&` 一起复制进去。

**Q：token 过期了怎么办？**
A：不用管。每次点【开始打卡】都会重新换取 token。

**Q：能改跑步区域吗？**
A：区域是服务器下发的，App 只负责从里面挑一个生成闭环。
跑一次【连接】就能看到你这学期有几个可用区域。

**Q：中间断了怎么办？**
A：重来。但注意别在跑步过程中手动停止 —— 小程序那边手动停止会导致这次作废。
